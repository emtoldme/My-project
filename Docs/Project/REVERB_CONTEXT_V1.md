# 第一部分：项目基本信息

## 1. 项目定位

**中文名称：**《麦田里的混响》

**英文名称：** Reverb in the Rye

**游戏类型：**
- 3D Survivor-like（类幸存者游戏）
- 机制驱动的装备构筑
- 多关卡重复挑战
- 环境叙事与碎片化 Lore
- 具有音乐表现力的实时战斗

**目标平台：** Windows PC 优先。

**基础引擎：** Unity 6，C#。

**渲染方案：** 优先沿用现有 URP 项目，不擅自更换渲染管线。

**镜头形式：** 俯视斜角的 3D 摄像机。

**制作方向：**

这是一款小规模独立游戏，采用 AI 辅助开发，但以实际可玩性、机制协同、视觉效果、音乐体验和个人化叙事为目标。

项目不追求堆叠不必要的复杂技术，也不追求单纯的功能数量。

我们希望通过少量可组合的机制、精心制作的资产，以及经过反复测试的战斗体验，逐步形成完整作品。

## 2. 核心开发原则

1. 先实现可运行的最小原型，再决定是否扩大制作规模。
2. 游戏设计允许通过实际游玩不断改变，不得将早期策划视为不可修改的技术需求。
3. 优先复用现有 Unity 项目及成熟工具。
4. 不为了架构完整性提前开发大量暂时用不到的系统。
5. 通过小规模独立技术实验检验复杂想法。
6. 明确区分已实现、已验证、仅有原型、尚未验证和技术设想。
7. 对项目现有功能保持兼容，不擅自推倒重建。

# 第二部分：艺术与世界观

本部分帮助你理解游戏的制作意图，不授权你自行制作正式艺术资产。

## 1. 核心美学

Rustpunk（铁锈朋克）× Rural Folk Horror（乡村怪谈）× Psychedelic Audio（迷幻音波）

整体采用 Stylized PBR，即具有真实材质基础的风格化三维画面。

主要视觉特征：

- 1980 年代美国乡村
- 金黄色麦田、玉米地与乡间道路
- 生锈的联合收割机、拖拉机和工业设施
- 旧广播、磁带机、电视和模拟电子设备
- 破败的农贸市场、粮仓、墓园、汽车旅馆
- 异常广播与时空干涉
- 高对比度的电子荧光战斗特效

画面要从俯视摄像机下具有良好的辨识度。

## 2. 色彩叙事

**黄色：现实、土地、童年、生命**

代表玩家熟悉的乡村现实，以及逐渐流逝的个人记忆。

**红色：革命、历史、牺牲与抵抗**

代表小镇过去发生的社会冲突、集体行动和被掩埋的历史。

**蓝色：未来、技术、控制与时间异常**

代表广播塔带来的异常现象，以及试图消除不确定性的技术系统。

**品红色：干涉、自由与反抗**

代表不同时间与信号交叠后产生的力量，也是主角后期能力的主要视觉象征。

这些颜色是叙事与美术语言，并不要求你为其编写复杂的真实物理模拟。

# 第三部分：世界观与故事

## 1. 故事背景

故事发生于架空的 1988 年美国乡村小镇 Radio Mounds。

主角幼年生活于此，与几位童年朋友一起成长。

父亲在主角年幼时去世，主角随后跟随母亲搬离故乡。

多年后，母亲去世。

主角带着母亲的骨灰返回故乡，希望按照母亲的遗愿，把她安葬在父亲旁边。

但是主角发现，父亲的墓碑竟然消失了。

随着调查深入，主角发现整个小镇正在经历无法解释的现实异常。

建筑从地图上消失，历史记录不断变化，收音机播放来自未来的新闻，某些居民甚至开始忘记自己的亲人。

异常源头指向一座大型农业广播塔。

## 2. 小镇历史

1968 年，小镇曾经发生一场被官方称为“麦收骚乱”的社会运动。

农民、铁路工人和机械工人试图改变当地的粮食仓储与土地控制结构。

这场运动被称为“红色麦收”。

事件最终以第四粮仓的灾难和人员死亡告终。

相关历史后来逐渐遭到掩盖。

主角父亲曾与这段历史有关，并在后来的事故中死亡。

主角将逐步发现父亲所留下的录音、机器和历史证据。

## 3. 主要反派

暂定姓名：Walter Vane（沃尔特·维恩）。

身份：广播塔安全工程师及历史事件幸存者。

其核心心理不是传统意义上的破坏欲，而是对错误、意外和失控的极端恐惧。

他相信，只要人类继续尝试改变世界，就无法避免失败与伤害。

因此，他试图通过广播塔消除不确定性、修改现实与历史记忆，让世界进入永恒安全的停滞状态。

他最有诱惑力的承诺不是权力，而是：

“你已经做得够多了。剩下的交给我吧。”

他可以利用广播塔创造近似童年幸福时光的幻象，让人不必继续承受现实中的风险与失去。

## 4. 主角的立场

主角代表事实、责任、审判与公正。

但主角不是永远正确的英雄，也并非不害怕失去。

他同样希望父母仍然活着，希望回到幸福的童年。

他最终拒绝的，不是休息、幸福或安全，而是通过删除历史、否认事实与剥夺自由来获得永恒安宁。

## 5. 故事最终目标

主角逐步发现广播塔及小镇历史的真相，最终阻止广播塔继续抹除现实。

之后，他终于能够完成最初的愿望：

将母亲安葬在父亲身边。

游戏最终回归安静的乡村。

主角在老屋中修理父亲留下的收音机。

机器仍有杂音，但终于能够播放音乐。

故事的最终主题：

**世界仍然可能出错，但人仍然可以带着记忆继续生活。**

# 第四部分：叙事方式

本项目强调通过**游戏玩法、关卡结构、环境变化和声音**传递故事。

不希望频繁打断玩家。

避免依赖大量强制剧情对话、长时间过场动画和突然改变游戏类型的独立演出。

优先使用：

- 场景中的历史遗留物
- 旧建筑与工业设施
- 童年物件
- 反复经过同一空间时发生的变化
- 广播与无线电通讯
- 音乐、环境音与静默
- 敌人行为和关卡状态
- 关卡的开始与结束结构

故事情绪大致经历：

1. 好奇与理解
2. 逐渐不安
3. 深层恐惧
4. 奋力反击
5. 温暖与释然

这五个阶段是全游戏的叙事弧线，不代表每局游戏必须完整经历五幕，也不要求单局战斗持续进行大量剧情演出。

玩家可以忽略部分环境叙事，而仍然获得完整的战斗体验。

# 第五部分：核心游戏设计

## 1. 基础玩法

游戏是一款 3D 幸存者 Like。

主要循环：

移动与躲避 → 自动或半自动攻击 → 消灭敌人 → 获取资源与经验 → 选择升级 → 形成机制组合 → 应对不断增强的敌群。

游戏应保证：

- 移动响应清晰
- 战斗判定可靠
- 大量敌人同时活动时保持合理性能
- 敌我视觉辨识明确
- 装备组合能够明显影响游玩方式

## 2. 多关卡结构

游戏具有多个独立关卡。

每张地图拥有自己的：

- 乡村生态与环境
- 历史痕迹
- 战斗空间
- 敌人配置
- 关卡事件
- 风险与挑战
- 特色可玩内容

关卡暂定包括：

**秋收之路：** 金黄色的乡村田野，侧重童年与归乡。

**旧农贸市场：** 破败的街道与工业设施，侧重小镇衰败和异常入侵。

**第四粮仓：** 红色历史的遗留地点，侧重历史、恐惧与空间压迫。

**无线电荒原：** 广播塔周边异常区域，侧重技术控制、时空干涉与最终冲突。

以上均为策划方向，不代表已经确定具体地图资源或必须立即制作。

### 场景连续性要求

每局主要发生于一张连续的 3D 战场。

避免在正常战斗中频繁将玩家传送到不相关场景。

技术上允许不同关卡使用独立 Unity Scene，但不应为了实现普通地图事件而迫使玩家频繁加载或切换场景。

## 3. 装备定制

玩家可以在局外配置自己的初始装备。

装备不以大规模数值膨胀为主要成长方式。

设计重点为：

**较低的基础数值膨胀 + 明显的机制差异 + 强力的组合协同。**

装备可改变：

- 攻击方式
- 命中传播
- 作用范围
- 触发条件
- 状态效果
- 延迟与持续时间
- 移动与攻击之间的关系
- 不同攻击效果的相互作用

例如：

基础声波武器命中敌人；

延时模块使敌人短暂延迟后产生回声；

折射模块使回声继续传播；

两者组合后形成连锁打击。

这些例子仅用于说明技术需求，不代表最终装备内容已经确定。

## 4. 局内成长

玩家在战斗过程中不断获得升级机会。

升级允许已有装备产生新的机制组合。

同一装备在不同构筑下可以形成不同打法。

核心要求：

- 升级具备明显可感知的行为变化。
- 单件装备应当具有独立价值。
- 组合机制允许非线性成长。
- 不要求所有组合等强，但应避免明显唯一的最优答案。
- 能通过配置与测试快速添加新效果。

## 5. 解锁与难度

通过关卡挑战、特殊目标和更高难度解锁新内容。

奖励可以包括：

- 新装备
- 新模块
- 新构筑可能
- 新关卡
- 新挑战
- 新叙事线索

难度主要通过敌人行为、组合、空间压力和机制要求体现。

不希望单纯依赖极端提高敌人血量或玩家伤害数值。

应允许玩家通过调整构筑、改善操作或学习机制克服挑战。

# 第六部分：音乐和动态音频

音乐是本项目的核心艺术组成。

主要音乐方向：

- Shoegaze
- Math Rock
- Electronic
- Ambient
- Industrial
- 带有乡村民谣元素的氛围音乐
- 特定场景中的工业 Rap 与人声

主要叙事用途：

平静时期，音乐温暖、孤独、富有空间感。

异常出现时，引入磁带噪声、反向音效、不稳定节奏和电子声景。

战斗高潮时，音乐逐渐变得复杂、激烈。

结局则逐步移除复杂的电子与工业声音，回归简单的木吉他和乡村环境声。

## 动态音乐技术要求

技术层面允许尝试：

- 多音轨分层播放
- 根据敌潮强度改变音乐层次
- 根据关卡阶段切换音乐状态
- 基于 DSP 时钟的同步调度
- 音乐事件与战斗特效联动
- 武器音效与背景音乐之间的节奏关联

优先检查 Unity AudioSource 和 AudioMixer 能否满足需求。

如未来复杂度确实增长，再评估 FMOD 等专用音频中间件。

**重要：全部正式音乐、音效、人声、音乐分轨和艺术声音内容由项目负责人提供。**

你不得擅自把程序生成的简单旋律、蜂鸣器音、合成鼓点或随机音乐作为正式配乐交付。

技术验证可以使用明确标注的临时测试信号、静音资源或占位音频，但它们只能用于验证调度、同步与混音功能。

# 第七部分：美术与特效

## 1. 3D 美术

项目负责人负责提供或指定：

- 主角模型
- 敌人模型
- 武器与装备模型
- 动画资源
- 场景建筑
- 农业机械
- 环境道具
- PBR 贴图
- UI 美术
- 字体与图标
- 视觉概念和参考材料

这些资源可能通过 Blender、专业资产平台、图像生成或其他外部制作流程获得。

**你不负责擅自生产正式 3D 美术资源。**

如果技术测试需要模型，可以使用几何体、简单临时材质或现有灰盒模型作为占位。

这些占位内容必须清楚标记，不可宣称其代表最终美术质量。

## 2. 渲染

沿用当前 Unity 项目已经确认的渲染管线和相关配置。

技术验证方向包括：

- Stylized PBR 材质兼容
- Shader Graph
- 麦田植被风动
- 黄昏与夜间光照
- 雾效
- 金属与潮湿地面反射
- 受击发光与溶解
- 红蓝信号干涉
- 品红色声波效果
- 多对象场景渲染性能

任何昂贵的渲染效果都应提供性能分析和简化替代方案。

## 3. VFX

预期技术组合：

- Unity Particle System
- Shader Graph
- VFX Graph（按实际需求）
- Mesh 特效
- Trail Renderer
- C# 特效事件
- 必要的自定义渲染功能

优先将**游戏逻辑与视觉表现解耦**。

例如：

声波是否命中敌人由战斗逻辑判断；

粒子、光环、音效和动画只负责反馈。

## 4. 特殊游戏对象

游戏可能出现兼具交互、战斗及叙事功能的物体，例如：

- 异常收音机
- 广播中继站
- 故障农业机械
- 可破坏的工业设施
- 能影响附近敌人的广播装置

技术上应支持不同逻辑组件的组合，避免每添加一种特殊物体都必须重写整套战斗系统。

但不要在内容需求不足时，提前实现庞大的通用可视化节点编辑器。

当然，你可以主动提出有创意的技术方案，甚至挑战现有设计。

但建议应该通过可比较的原型和明确的技术分析来支持，而不是直接替换策划。

# 第十一部分：技术验证工作方式

以后每项任务尽可能遵循以下流程：

## 阶段 A：检查现状

先读取对应的工程代码和资源配置。

说明已经存在什么、哪些功能可以复用、哪些技术风险需要验证。

不要凭空假设项目没有相关系统。

## 阶段 B：提出最小实验

把目标缩小到可以单独观察结果的技术问题。

例如：

“验证两个装备效果能否通过统一战斗事件产生连续传播。”

而不是：

“开发完整的几十件装备系统。”

## 阶段 C：编写可运行原型

只编写技术验证所必需的代码。

优先使用现有灰盒环境和占位资源。

尽量隔离实验逻辑，避免污染正式关卡和核心框架。

## 阶段 D：实际测试

按照当前可用条件执行：

- 编译检查
- EditMode 测试
- PlayMode 测试
- 场景运行
- Development Build
- Profiler 测量
- 边界条件测试

无法执行的项目必须明确标记“未验证”。

## 阶段 E：结果交付

每项任务需要说明：

1. 原本要验证什么。
2. 实际实现或修改了什么。
3. 修改了哪些文件。
4. 哪些测试实际执行并通过。
5. 哪些测试失败或尚未执行。
6. 如何在 Unity 中复现和体验。
7. 已知问题与限制。
8. 是否适合合并到正式工程。
9. 是否需要项目负责人提供正式素材。
10. 下一步最值得验证的一个问题。

不要使用“工业级完成”“全面实现”“完美运行”等没有明确证据支持的表述。

# 第十二部分：当前阶段的目标

我们现阶段不要求立即开发完整的《麦田里的混响》。

也不要求开始制作全部剧情、美术、音乐或关卡。

**目前的主要目标是检查已有 S1 灰盒工程，为未来六个内容方向建立可验证的技术基础。**

六个方向分别是：

1. 特效与特殊游戏对象
2. 3D 画面与渲染
3. 美术资产导入与动画
4. 动态音乐与音效
5. 战斗、成长和装备构筑
6. 环境叙事与 Lore 触发

第一轮优先只验证这些方向的基本技术通路，尽可能形成六个独立的小实验。

候选实验包括：

**特效：**
一次攻击触发声波 Mesh、粒子和命中反馈。

**渲染：**
一个简单 Shader Graph 特效与现有 URP 场景兼容。

**美术管线：**
使用现有或临时测试模型，验证导入、材质和 Prefab 引用。

**音频：**
利用占位音频验证两条同步音轨的动态混音。

**装备：**
使用两个简单效果模块，验证事件触发与组合。

**环境叙事：**
玩家经过某一物体后，依据关卡状态改变其显示和音频状态，且不打断战斗。

这些只是候选项。优先根据真实工程状况选择最有价值的实验。

# 第十三部分：你的第一项实际任务

现在请先执行一次**技术基线审查（Technical Baseline Review）**。

要求：

1. 检查你当前能够访问的 Unity 项目。
2. 识别现有功能、代码结构和已经具备的技术基础。
3. 评估当前工程是否能支持上述技术实验。
4. 找出可能阻碍下一步验证的问题。
5. 提出最多三个优先级最高的小规模技术实验。
6. 若环境允许，实际运行现有测试并报告结果。
7. 暂时不制作正式美术、音乐或大型新系统。

**首轮以审查和验证为主。未经进一步授权，不进行大规模代码改动或架构重构。**

输出一份简洁、具体、基于真实工程证据的技术审查报告。

最终目标不是尽快生成大量代码，而是帮助项目负责人持续地、低成本地测试创意，并逐步将验证成立的技术整合成真正好玩的游戏。

项目负责人将持续提供美术、音乐、叙事与玩法反馈。

你需要成为可靠的技术实验与实现伙伴，而不是替代创作者的自动游戏生成器。
