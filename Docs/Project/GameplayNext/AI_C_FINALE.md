# GP-C：终局首领

给AI-C的任务卡。GP00 v1接口已固化，从GP00_RELEASE.md指定共同基线开始开发。请先读本轮README、CONTRACTS.md和工程AGENTS.md。你负责首领招式与终局请求，HP、伤害、掉落和胜负仍归宿主。

建议分支`gameplay/gp-c-finale`，独立目录。所有权：新增`Assets/Waffle/Scripts/Rules/Finale/`及自己的必要测试/说明；不修改A的遭遇目录、共享CombatModule/RunSimulation、主场景或HUD。

## 目标

一只无需新武器也能击败、预警能读懂、有两种招式的终局首领。首领与普通敌人复用同一实体/HP/死亡结算，不建立额外战斗引擎。

## 内容

1. 首领在9:00发出约3秒出生预警后请求生成，在合法可见区域进入战斗，不直接出生到玩家脚下；首领最多一只，不参与普通远离挪位。
2. **三连落波。** 逐次锁定玩家位置，给出圆形危险预警后依次激活；同时锁定未激活圆最多3个，命中与取消按共同攻击契约。
3. **扩散声环。** 圆环从首领附近扩散；提前给出至少约1.2秒预警，几何为真实内外半径。以正常移速存在可行逃离路径，闪避无敌可作为另一种处理方式，不做必须拥有某件装备的检定。
4. HP降到50%后缩短部分招式间隔，不新增第三招，也不清空/重置既有HP。转阶段不在同tick堆叠两种无预警攻击。
5. 输出首领阶段、实体键、真实HP/MaxHP映射、危险快照与结束请求。首领普通攻击/掉落预算由宿主统筹。
6. 新模式BossClear：首领死亡被T7确认后请求胜利；10:00首领仍存活则请求超时失败。玩家同tick死亡优先。旧SurvivalOnly模式保持原胜负口径。

HP与招式频率给出可调初值及设计依据；先在现有早期/中期两套有效构筑上做短测，再由Codex统一调平衡，不先承诺固定击杀秒数。

## 交付切片

- C1：单招首领行为，绑定宿主EnemyState的接口与死亡取消检查。
- C2：第二招、半血阶段、终局请求与截止边界检查。

## 必须通过

- 首领只生成一次；出生预警期间不攻击；预算不足不会刷出重复实体。
- 两种招式共用宿主危险执行器，预警与实际形状/时序一致，死亡后撤销未结算危险。
- 暂停/升级冻结，回池/重开清空；不给首领额外MonoBehaviour时钟。
- 玩家死亡与首领死亡同tick算失败；仅首领恰在10:00死亡算胜利；旧模式不被改变。
- 奖励、击杀和胜利最多各结算一次；不因动画/特效播放完而判定死亡。
- 首领阶段不与旧9:30精英事件叠加，普通敌人降压由Codex/A适配，不自己另起刷怪循环。

## 边界与提交

先复用现有精英外观并由D提供临时招式表现。不自行生产正式模型/音乐，不复制普通敌人HP、不重写武器伤害或玩家无敌。

提交分支/PR或SHA、改动文件、两种招式时序图或表、检查结果、终局与实体适配请求、已知问题。独立规则检查通过不代表首领实战已验收。
