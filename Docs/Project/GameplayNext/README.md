# 下一轮玩法开发与分工

2026-10-13。状态：GP00接口与宿主已实现，发布说明见 [GP00_RELEASE](GP00_RELEASE.md)。A/B/C/D内容仍以各任务实际交付为准。按四位外部AI独立开发、Codex统一接线的协作方式安排。本目录是新一轮提案，不恢复已移除的TASKS_01..08，也不把旧地图/UI提案视为已批准需求。

## 这一轮要得到什么

把当前《秋收之路》做成一局有变化、能读懂危险、能选择冒险收益、能通过首领战结束的9–10分钟体验。

这一轮交付：保留追击敌人，新增冲锋者和远程落波者；两次可选声学装置调谐；一只拥有两种攻击的终局首领；真实的预警、目标、首领血条和结算。继续使用现有6攻击/14被动/3进化/4拾取，不先扩武器数量、局外经济、存档、多人或另外三图。

天气仍是表现系统；F6切换天气不会改变伤害、敌人AI或玩家移动。新增危险必须在雨天、闪电、植被和技能特效下仍能看清。

## 核对过的基线

- 本地提交：`20d26e6`，完整ID `20d26e639e600b1be27903ea074463dc6e446358`；包含动态光影与天气。用户工程为`My project`，整合工程为`My project-integration`。

- 当前普通敌人与精英共用追击移动，精英主要改变属性；已有时间波次、推进、包围、精英奖励和构筑系统。

- 新玩法接线归GameLoop → RunSimulation → CombatModule。现有ICombatRuleExtension只有直接命中/弹体后置钩子，不足以直接装入敌人AI或地图目标；必须先完成GP00。

天气与GP00接口共同发布在独立开发分支，具体基线见GP00_RELEASE.md；origin/main不自动代表该基线。各任务从共同提交开始并在独立目录/分支开发，不直接推main或覆盖用户工程。

## 开发顺序与合并关口

1. **GP00先行。** Codex创建最小契约和宿主接线点，保持旧模式可玩；编译通过后记录共同提交。共用契约已经固化，先读[实际API说明](GP00_API.md)，再按发布的共同提交开发。
2. **四条线并行。** A/B/C按冻结契约写独立规则模块；D先做可复用预警和只读HUD。跨所有权文件的修改以适配请求交Codex处理。
3. **先合A。** 一种敌人接线试玩后再接第二种，验证预警、命中、冷却、死亡清理。之后启用完整五段混编，避免一次改变全部压力来源。
4. **再合B。** 先开第一次调谐，再开第二次，验证可放弃、可回到目标、奖励一次且不破坏升级队列。
5. **再合C，最后收D。** 先接首领攻击，再启用新终局规则；D用实际快照替换联调数据。单独运行的样板不是最终交付。
6. **完整局与发布。** 完成[验收清单](ACCEPTANCE.md)，保存可回滚提交，生成新的Windows试玩包。旧天气试玩包保留。

每条线先提交一个可审查的小切片，接口或玩法方向有问题时及时调整，不等全部写完才联调。不承诺未经评估的固定完成日期。

## 本轮体验初案

以下时间、占比与预警时长是可调初值，不是平衡定稿。现有地图几何不重做。

| 局内时间 | 体验目标 | 新增内容 |
|---|---|---|
| 0–2分钟 | 认路、升级、学习规避 | 保留追击；约1分钟后少量冲锋者 |
| 2–4分钟 | 移动路线开始有选择 | 引入远程落波者；2:30出现第一次可选调谐 |
| 4–6分钟 | 构筑开始成形 | 三类混编，保留4:00精英/现有成长奖励 |
| 6–9分钟 | 冒险拿补给或保持走位 | 6:30第二次可选调谐；保留8:00精英，压力按预算增长 |
| 9–10分钟 | 明确终局挑战 | 9:00首领预警后出场，降低普通刷怪压力；击败首领立即胜利，10:00仍未击败则失败 |

保留`SurvivalOnly`旧模式用于回归，新增模式暂名`BossClear`。玩家死亡优先于同一tick的首领死亡；9:00前不能刷出首领，战斗窗口从9:00预警到10:00封顶。首领和精英同时出现的压力由Codex统一调度，首领阶段禁用原9:30额外精英事件。

## 共同交付要求

- 一人一份独立工程目录和`gameplay/gp-*`分支，同一共同基线；不得四个人同时改`My project`。
- 每次交付提供提交SHA/分支或PR、改动路径、实际接线状态、复现步骤、必要检查结果、已知问题、给Codex的适配请求。创建PR只对开发分支，不直接合main。
- 对规则变化补必要的边界检查，复用现有测试程序集；不扩全面测试平台或全武器平衡矩阵。只有源码编译或独立样板时，明确标注未在真实主场景联调。
- 不手写场景YAML，不改渲染管线、包依赖、天气、美术资产、R1音频或既有GUID。正式新美术/音乐需求列清单，不能自行替换现有资源。
- Codex逐个审查、接线和构建；用户决定实际好玩程度、最终节奏与视觉可读性。
